# SAS 실행 런북

실제 실행 여부는 사용자 SAS 세션의 로그·ODS 결과로 확인한다.
교육 최종 발표의 중심은 유형·유사도별 실패 조건이다.

## 준비

1. 최신 번들 내부 `sas/`, `data/`, `reports/`, `outputs/`를 `/home/student/`에 배치한다.
2. `CHECKSUMS_SHA256.txt`와 `MANIFEST.json`을 보관한다. 이전 CSV와 새 코드를 섞지 않는다.
3. `proc options option=encoding value; run;`으로 UTF-8을 확인한다.
4. `outputs/` 쓰기 권한을 확인한다. 04를 실행할 때만 추가 WORK 공간·라이선스를 확인한다.

## 실행

`/home/student/sas/00_RUN_ALL.sas` 전체를 실행한다.
순서는 07 → 01 → 02 → 03 → 06 → 05이며 04는 선택 실행이다.
02는 유효한 OOF 입력이 있을 때 적합한다. OOF 부재로 02를 건너뛰면 메타 회귀는
미완료로 남지만, 기존 점수 기반 ROC 비교·그림은 계속 만들 수 있다.

단독 실행 시 07은 독립 실행하고 내부 분석은 01부터 시작한다. PROC IMPORT가 대부분
비어 있는 OOF 열의 타입을 잘못 추정하지 않았는지 `proc contents`로 확인한다.
train OOF와 validation/test 일반 추론 점수를 혼동하지 않는다.

## 성공 판정

| 단계 | 확인 내용 |
|---|---|
| 공통 | 입력 버전, UTF-8, ERROR, WARNING 원인 |
| 07 | 전체→연도 적격→주요 유형 표본 흐름, 제외 미탐 수, 동일 범주 처리 |
| 07 | 수렴·분리, 동일 관측 수, joint year 검정, OR CI·관측/예측 곡선 |
| 01 | 실제 사용 바이트 기준 잘림, ID·분할·라벨·확률 범위 |
| 02 | train OOF 유효성, validation 임계값·적합 경고 |
| 03/06 | 같은 행의 ROC-AUC 비교, 결측에 따른 제외 행 |
| 05 | 입력 산출물에 연결된 그림, 모델·표본·전처리 단계 |

07은 Python과 같은 추정 설정이면 수치 대조가 가능하다. 차이가 나면 데이터형·기준범주·
제외 행·수렴·버전을 확인한다. 02는 Python과 규제·가중치가 달라 계수 부호를 합격
기준으로 쓰지 않는다. 어떤 p값도 미리 정한 합격 숫자가 아니다.

## 보관과 오류 대응

`outputs/`의 단계별 로그·HTML·실행 상태 CSV를 입력 manifest와 함께 내려받는다.
다음 실행 전 이전 결과를 날짜별 폴더로 보관한다. ERROR/WARNING 및 누락 단계를
검수한 뒤 완료 여부를 결정한다. 파일 존재만으로 성공이라고 표시하지 않는다.

오류가 나면 첫 ERROR, SAS 버전, 입력 해시를 기록한다. OOF 검사가 실패하면 입력을
대조하며 in-sample 점수로 우회하지 않는다. `%abort cancel`이 실행을 중단한 경우
최종 실행 상태 CSV가 없을 수 있으며, 완료로 간주하지 않는다.

발표에는 데이터 감사, 실패 확률·CI, 표본 제외 영향, ROC-AUC 차이를 골라 쓴다.
KISA 악성·URL 포함 자료와 선별 정상 도전셋은 현장 대표 표본이 아니다. 현장 유병률을
모르면 조건부 시나리오로 표시한다. 수신 문자 총수만으로는 유병률을 구할 수 없다.
